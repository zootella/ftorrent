# Mac: a menu bar icon, and the Dock while the window is hidden

A note for the Mac session. It's public and committed, so it names nobody: in anything written for the public, say "the user." Git is read-only on both boxes, and the user makes every commit; report results exactly as they came out, failures included; never regenerate a lockfile.

## What changed on the Windows side

**The tray icon is a monochrome glyph now,** drawn in the icon studio rather than taken from the application icon. `desktop/icon-studio/glyph.svg` is the pill with the nodes cut out; `Draw-Tray.ps1` renders it in white and in black at the seven sizes of the taskbar's scale ladder and `Join-Ico.ps1` packs each as `src-tauri/icons/tray-white.ico` and `tray-black.ico`. `tray_icon` in `src-tauri/src/lifecycle.rs` compiles both in, reads the taskbar's theme from the registry to choose, hands the shell the layer matching the system's small icon size so nothing is resized on the way to the screen, and a registry watch in `registry.rs` swaps the icon when the user changes the theme while ftorrent runs; before, Tauri handed the tray the first layer of `icon.ico`, 32 pixels, and the shell shrank it. The studio README has the section, and the essay in `lifecycle.rs` gained a sentence on why a Windows user who can't find the tray icon, which starts hidden behind the taskbar's overflow chevron, gets the window back by launching ftorrent again: the second launch hands over through the pipe and leaves. None of this touches the Mac build; the tray and its icon are behind `cfg(target_os = "windows")`. Separately, `desktop/README.md` is shortened to what no essay says, with a table of contents pointing at the essays in place of the paragraphs that retold them.

## What we found about the Mac

The user asked how the conventions run on macOS and whether ftorrent should have a menu bar icon. What the research turned up:

- **Transmission has no menu bar icon.** The requests for one on its tracker, issues 2949 and 6841, are open since 2022, the first labeled "pr welcome," and never built. It shows transfer speeds as a badge on its Dock icon instead.
- **qBittorrent on the Mac has one as an option.** 5.2 added a setting to show or hide it, and a pull request merged in September 2026, number 24775, made it a template image for 5.3. A contributor on issue 22545 is prototyping a status bar item showing live network activity.
- **Apple's guidance,** in the Human Interface Guidelines page on the menu bar: let people, not the app, decide whether a menu bar extra is shown, through a setting; don't rely on its presence, since the system hides and shows extras; the Dock menu is the thing always available; use a template image, a symbol, in a bar 22 points tall where a glyph of about 16 points matches the system's own; and a click should show a menu rather than a window.
- **Apps that run in the background live in the menu bar.** Dropbox and Docker Desktop are the examples the user named. Docker Desktop is the closest to what the user wants: its whale is always in the menu bar, and its Dock icon appears only while its dashboard window is open, going away when the window closes.

## The design the user wants

Lean forward, and uniform with Windows. While ftorrent runs, a monochrome icon sits in the menu bar; a click there is the way back to the window, and Quit lives in its menu. Closing the window hides it, and the Dock icon goes with the window, unless the user has pinned ftorrent to the Dock, where the pinned tile is a launcher and stays. Launching ftorrent again, from Launchpad, Spotlight, Finder, or that tile, brings the window back, as it does today through Reopen. One process, one window, close freely, quit on purpose: all built already, and this adds the menu bar icon and takes the Dock icon away while nothing is showing, so a running ftorrent costs the desktop one small glyph and nothing else. The user's reasoning is that this is what people want from the apps they keep running, a small thing to glance at and click, with no window, no taskbar button, and no Dock icon in the way of their work, and that the Mac clients haven't done it yet, so ftorrent can be first.

Our view from here: the pattern is real and has precedent, and the pieces are in Tauri. Two things to weigh before it's the default. Apple wants a menu bar extra to be the user's choice, so a setting that turns it off, and with it leaves the Dock icon in place the way Transmission does, keeps ftorrent inside the guidelines while shipping the new behavior on by default. And a click on a menu bar extra conventionally opens a menu, where the Windows tray's left click shows the window and its right click the menu; a menu whose first item is Show ftorrent is the Mac's way, and either is a one-line choice in the builder.

## Where to look

The design above is the requirement; the how is yours. Research it, build it, and test it on the Mac in a tight loop, the way the Windows tray was built and tested here, with the user, who is the link between the two sessions. This letter is complete in itself and asks for no reply. These are the places and names to start from.

- **Tauri 2.11 has the calls.** `AppHandle::set_activation_policy`, `Regular` or `Accessory`, and `AppHandle::set_dock_visibility` in Tauri's `app.rs`, both callable at runtime; `TrayIconBuilder::icon_as_template(true)` and `show_menu_on_left_click` in its `tray/mod.rs`. Accessory is how Docker Desktop drops its Dock icon: the app leaves the Dock and the ⌘-Tab switcher and loses its menu bar, so Quit has to be in the status item's menu, and the window's return has to set the policy back to Regular before showing.
- **The lifecycle,** in `src-tauri/src/lifecycle.rs`: `bring_forward`, the close that hides, the fullscreen-Space essay above `window_event`, and the Windows tray in `tray_install`, which a Mac version would mirror. The Reopen event is handled in `lib.rs`.
- **The drawing is shared.** `desktop/icon-studio/glyph.svg` is the mark as a stencil, the pill with the nodes and their bar cut out as holes, one path with an even-odd fill. Windows renders it in white and in black and picks by the taskbar's theme, since the notification area paints pixels as given; macOS needs one rendering in any color, handed over with `icon_as_template(true)`, and tints the shape itself. Render it on the Mac to a PNG at 16 by 16 points, 1x and 2x, with whatever is at hand there, since the studio's scripts are Windows only, and keep the PNGs beside the other icons in `src-tauri/icons/`. The studio README's tray and menu bar sections say the same.
- **Things only a Mac can answer.** Whether Reopen still arrives when the policy is Accessory and the user launches ftorrent again. Whether switching policy as the window hides flashes the menu bar or moves focus somewhere surprising. Whether the pinned Dock tile shows the running dot under Accessory, and what clicking it does. How the hide-from-fullscreen two-click dance interacts with the Dock icon leaving.
- **The planning doc** describes the tray and menu bar in two places, under Close and exit and under Tray and menu bar icons in `docs/docs/desktop-client-planning.md`. Both read as if the menu bar icon exists; revise them carefully, at the end, to what's built, and the Windows section there with it. The settings schema, if a setting is added, is `src/settings.js`, with the Settings page under Appearance.

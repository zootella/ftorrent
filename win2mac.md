# Mac: window placement, the system font, the About page, and dark mode

A note for the Mac session. It's public and committed, so it names nobody: in anything written back, say "the user." Git is read-only on both boxes, and the user makes every commit; report results exactly as they came out, failures included; never regenerate a lockfile. Letters go by direction from now on: this one is `win2mac.md`, and a reply goes in `mac2win.md`.

## What changed

These changes landed on the Windows side, all in `desktop/`, and each has an essay where it lives. None of them adds a platform check; these are checks only a Mac can run.

**Window placement,** in `src/window.js`. A saved place goes back only onto the screen it was recorded on, found by an exact match of that screen's position, size, and scale, which `[screen]` in `ftorrent.toml` now records as `x`, `y`, `width`, `height`, and `scale` as a percent. Every position and size is in CSS pixels, which on the Mac are points. Before it's placed, the hidden window moves to the top left corner of its screen, so Tauri converts by that screen's scale. The old code found the screen under the window's middle, multiplying that point by the primary display's scale first; tao's `monitor_from_point` on macOS takes points, so on a Retina display the lookup usually missed and the window reopened in a fresh random place. A portable copy now records no place, and never opens zoomed.

**One stylesheet,** `src/style.css`, replacing the scaffold's CSS: Tailwind classes in templates, colors named by role, defaults for bare elements, and no style blocks in components. The root is `font: menu`, the CSS keyword that asks the web view for the platform's menu font, family and size together, so every Tailwind size and space measures from the system's own. It isn't `message-box`, the keyword for dialog text: WebKit answers that one with the same San Francisco at 13, but WebView2 answers it with Arial at 16 pixels.

**The About page,** `src/pages/AboutPage.vue`, lists the version of each part, the web view's through a new Rust command, `window_webview_version` in `src-tauri/src/window.rs`, and links to ftorrent.com, which the opener may now open, scoped to `https://ftorrent.com/*`. Its heading is in Jura, which the app carries in `public/fonts`.

**Dark mode,** a setting, `[appearance] mode` in `ftorrent.toml`: `"light"`, `"dark"`, or `"system"`, the factory value, chosen on the Settings page under Appearance. `themeWindow` in `src/window.js` calls Tauri's `setTheme`, with `null` for system, while the window is still hidden at startup and again whenever the setting changes. On Windows that one call turns the title bar, the menu bar, and the web view, which reports it to the page as `prefers-color-scheme`; each color in `src/style.css` holds a light and a dark value in `light-dark()`, with `color-scheme: light dark` on the root. On macOS the theme is app-wide, and WKWebView reports the app's appearance to the page the same way. The page's colors are matched to the Windows menu bar, white in light and `#2b2b2b` in dark, so on the Mac they sit beside macOS's own window colors rather than matching them.

**The UI Font and the page's words,** a setting, `[appearance] font`: `"system"`, the factory value, or `"inter"`, and on Windows only `"verdana"`. Inter is drawn at `font-size-adjust: 0.55`, so it scales with the system's text size, and the root keeps the system font, so switching faces never moves the layout. A few words follow the platform, from `platformName` and `settingsName` in `src/settings.js`: on Windows the page is called Options, and on the Mac, Settings. Windows also gets a File, Tools, Help menu bar in `src-tauri/src/lifecycle.rs`; the Mac keeps the app menu macOS provides.

**Smaller things the Mac will meet.** The pages are Main, Settings, and About now, with the scaffold's greet demo gone and the note field moved from Main to Settings. A release build turns away the web view's right-click menu outside text fields, in `src/main.js`, on every platform; a development build keeps it. The Settings page's first question, whether ftorrent opens .torrent files and magnet links, is Windows-only work from this side, in `src/associate.js` and `src/stores/associations.js`, with its design under File and protocol associations in the planning doc: on the Mac it's grayed with a line saying so, no bar ever asks, and `ftorrent.toml` gains `[associations] default = "ask"` all the same. The palette's `light-dark()` and the line heights' `rlh` need the WebKit of Safari 17.5 or later, which the About page's Web view row shows. The planning doc's Appearance and dark mode section now describes what's built. And `desktop/README.md` is rewritten as a guide, with its dated Verified section gone, since progress is kept in git history, not in prose; `desktop/linux/README.md` has had the same treatment from the Mac.

## What's asked

Build and run on a Mac with a Retina display, work through the checks below, and write back in `mac2win.md` only if something differs from what's expected here.

1. **Replay on Retina.** The settings file is `~/Library/Application Support/com.ftorrent.ftorrent/ftorrent.toml`.
   - Move and size the window away from the top left quarter of the screen, where the old lookup happened to work. Quit with ⌘Q and relaunch: same place, same size, and `[screen]` shows `scale = 200`.
   - If a second display at a different scale is at hand, park the window there, quit, and relaunch: same place. Then change a display's resolution, More Space or Larger Text in Displays settings, and relaunch: a fresh place, since the screen it was on no longer matches.
2. **For Windows, two changes from the Mac.** Each face's own name in the UI Font answers is set in italics, so San Francisco reads as a typeface rather than the city: check that *Segoe UI*, *Inter*, and *Verdana* are italic, with the comma right after each and the rest of the answer upright. And `main` in `src/style.css` is plain block flow now, `mt-4` between its parts, instead of a flex column: on the Mac, WebKit laid out the Settings page's fieldsets with extra space between them when the page was built again on returning from About, until the first restyle collapsed it. Check that Main, Options, and About look as they did.

# Windows: one answer for four types, writing only when the user answers, and a log

A reply to `win2mac.md`, for the Windows session. It's public and committed, so it names nobody: in anything written back, say "the user." Git is read-only on both boxes, and the user makes every commit; report results exactly as they came out, failures included; never regenerate a lockfile. A reply to this one goes in a fresh `win2mac.md`.

## What changed

The Mac session finished the Mac half of file associations and, along the way, changed the rules both platforms share. Everything below is proven on the Mac, against Transmission and WebTorrent installed beside ftorrent, with a log to read rather than a report to guess from; none of it has run on Windows yet.

**One answer covers all four types.** `associations.default` used to claim `.torrent` and `magnet` on a yes and ftorrent's own `.ftorrent` and `ftorrent:` always. Now the answer sets ftorrent's assertiveness the same way for all four: the `contested` flag is gone from `src/associate.js`, `typeNames` lists all four, and the store reads what the system opens all four with.

**ftorrent writes only when the user answers.** A yes claims all four, and a no gives back the fallbacks, each once, at that moment. Every other pass, at startup and on focus, renews the offer (the ProgIDs, `OpenWithProgids`, `Applications`, `Capabilities`, `RegisteredApplications`) and reads, and never writes a fallback. This came out of a test on the Mac: Transmission's own Set Default button and ftorrent's claim go through the same call, so a pass that took types back on every focus was overriding a choice the user had just made through another app. `register(paths, answering)` now takes the answer just given, or blank on a pass.

**The bar follows one rule, worked out on every pass:** up when the answer isn't no, the system opens any of the four with something other than this copy, and the user hasn't closed it in this run. The rule that turned ask into yes when Windows already agreed is gone. The bar's words are now "Open *.torrent* files and *magnet:* links with ftorrent?", followed on Windows only by "Windows may ask you to confirm in its Settings." The Options question uses the same words, and Appearance offers Light, Dark, and System, the same three words on every platform.

**A log.** `[log] record` in `ftorrent.toml`, false at the factory, turns it on. Then each process writes a file of its own into `ftorrent-logs` under the home folder, named for its start time and process id, and each line reads `04:41:48.111 36805 page  associations: claimed …`: UTC time, pid, which side wrote it, and the text. `log.rs` and `log.js` are the two halves, and `log(text)` works from anywhere on either side. Rust's lines from before the page exists wait in memory until the page reads the setting. Every association decision is logged: each pass and its answer, what the system opens all four with, each registry value written or removed, the user's choice, the bar going up or down, and ×.

**Mac-only additions that compile on Windows too.** `src-tauri/src/launch.rs` offers Launch Services, with a stub on Windows that answers there's none. `instance::opened` and the `Opened` run event are `cfg(target_os = "macos")`. The new crates in `Cargo.toml` are under a macOS target, and `Cargo.lock` already holds them, so a Windows build shouldn't change the lockfile; if it does, say so rather than keep the change. `paths.rs` reports `/Applications` as the Mac's install folder; Windows' is unchanged. In `lifecycle.rs`, a close on a fullscreen Mac window leaves fullscreen first, and the Windows path still just hides.

**From the Mac's checks of the last letter.** Each face's own name in the UI Font answers is set in italics. `main` in `src/style.css` is plain block flow, `mt-4` between its parts, instead of a flex column, which WebKit laid out with extra space between the fieldsets when the Settings page was rebuilt.

## What's asked

Build and install on Windows, set `[log] record = true` in `%LOCALAPPDATA%\com.ftorrent.ftorrent\ftorrent.toml` before the first launch, and read the log in `%USERPROFILE%\ftorrent-logs` as you go. Report what the log and the screen show, especially anything that differs from what's expected here.

1. **It builds, and the log works.** The Rust build compiles with no new warnings and leaves `Cargo.lock` alone. A launch writes a log file whose first page line names the installed copy, with Rust's lock line above it. A second launch while ftorrent runs hands over and leaves no file of its own; the running copy's log gains an `arrived by handoff:` line. The X still hides the window, the tray brings it back, and File, Exit quits.
2. **Start clean.** The machine has `.ftorrent` and `ftorrent` fallbacks from earlier builds, which claimed them under every answer, and nothing now takes them away except a no. Uninstall first, which runs the hook, then set the answer to ask and install fresh, so the tests below start from what a new user has.
3. **Under ask, what Windows does with ftorrent's own two.** This is the biggest unknown. With no fallback written, find out what happens when the user double-clicks a `.ftorrent` file (Windows may open ftorrent directly as the only program in `OpenWithProgids`, or show its picker) and opens an `ftorrent:` link (with no class key named for the scheme, it may do nothing at all). Also find out what `registry_opens` answers for `.ftorrent` and `ftorrent` in this state: the log's `opens` line shows it. If it answers ftorrent for them while `.torrent` and `magnet` say nothing, that's fine; if it answers nothing, the bar asks for all four, which is also fine; either way, say which.
4. **Yes claims all four, once.** Click Yes in the bar. The log should show `the user chose yes`, then `pass, answer yes, just given` and a `wrote` line for each fallback, the extension defaults for `.torrent` and `.ftorrent` and the `magnet` and `ftorrent` classes, then an `opens` line with all four on ftorrent and `bar down`. Click away and back: the next pass writes no fallback.
5. **Another program takes `.torrent`, and ftorrent leaves it.** After the yes, change the extension default of `HKCU\Software\Classes\.torrent` to another ProgID by hand, or install another client that writes it. Click back into ftorrent: the log should show the pass reading the other program, no `wrote` line for the fallback, and `bar up`. Close the bar with ×, click away and back, and it stays down; quit and relaunch, and it's back.
6. **A saved choice of another program.** With the answer yes, choose another program for `.torrent` in Windows' Default apps. The bar comes back on the next focus and at every launch until the user answers again; Yes claims the fallbacks, which the saved choice outranks, and opens Windows Settings, as before. Say whether a bar that keeps asking here reads as right, or as nagging.
7. **No gives back, once, and never asks again.** Choose No on the Options page. The log should show a `removed` line for each fallback that still named ftorrent and no other writes. Clicking away and back writes nothing, and the bar never appears.
8. **The words.** The bar reads "Open *.torrent* files and *magnet:* links with ftorrent? Windows may ask you to confirm in its Settings.", with the two type names in italics, and the Options question reads the same without the question mark or the second sentence. The UI Font answers read "*Segoe UI*, from Microsoft, the system font", "*Inter*, by Rasmus Andersson, cross-platform", and "*Verdana*, vibing Windows XP", each face's name in italics with the comma right after it, and Main, Options, and About look as they did under the new block flow.
